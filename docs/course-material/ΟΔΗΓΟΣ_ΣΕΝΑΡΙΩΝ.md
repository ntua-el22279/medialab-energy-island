# MediaLab Energy Island — Οδηγός σύνταξης αρχείων σεναρίου

Συμπληρωματικό υλικό της τελικής εργασίας στο μάθημα Τεχνολογία Πολυμέσων.

Ο οδηγός περιγράφει τη μορφή των αρχείων που ορίζουν ένα σενάριο. Η μορφή είναι **δεσμευτική**: η εφαρμογή σας θα ελεγχθεί και σε σενάρια που δεν σας έχουν δοθεί, γραμμένα ακριβώς με αυτούς τους κανόνες. Μαζί με τον οδηγό δίνονται δύο έγκυρα σενάρια, `a` και `b`, που μπορείτε να χρησιμοποιήσετε ως παραδείγματα και για τα τεστ σας.

## 1. Οργάνωση φακέλων

Κάθε σενάριο βρίσκεται σε δικό του υποφάκελο του `medialab/scenarios/`:

```
medialab/
└── scenarios/
    ├── a/
    │   ├── island.json
    │   ├── catalog.json
    │   └── days/
    │       ├── weights.json
    │       ├── winter.csv
    │       ├── spring.csv
    │       ├── summer.csv
    │       └── autumn.csv
    └── b/
        └── ...
```

Το όνομα του υποφακέλου είναι το αναγνωριστικό του σεναρίου. Τα ονόματα των αρχείων `island.json`, `catalog.json` και `days/weights.json` είναι σταθερά. Τα ονόματα των αρχείων CSV είναι ελεύθερα και ορίζονται μέσα στο `weights.json`.

Όλα τα αρχεία είναι κωδικοποιημένα σε **UTF-8**. Ο δεκαδικός διαχωριστής είναι πάντα η τελεία (`0.75`, όχι `0,75`).

## 2. Μονάδες μέτρησης

| Μέγεθος | Μονάδα |
| --- | --- |
| Ισχύς | kW |
| Ενέργεια, χωρητικότητα μπαταρίας | kWh |
| Ταχύτητα ανέμου | m/s |
| Κόστος επένδυσης, κόστος εκκίνησης | € |
| Κόστος καυσίμου | € ανά kWh που παράγεται |
| Εκπομπές | kg CO₂ ανά kWh που παράγεται |
| Διάρκεια ζωής | έτη |
| Στάθμη μπαταρίας, απόδοση | κλάσμα 0–1 |

Επειδή το βήμα της προσομοίωσης είναι μία ώρα, η ισχύς σε kW μιας ώρας ισούται αριθμητικά με την ενέργεια σε kWh της ίδιας ώρας.

## 3. Το αρχείο `island.json`

Περιγράφει τον χάρτη, τον προϋπολογισμό, τις υφιστάμενες μονάδες και τις υποψήφιες θέσεις.

### 3.1 Πεδία πρώτου επιπέδου

| Πεδίο | Τύπος | Υποχρεωτικό | Περιγραφή |
| --- | --- | --- | --- |
| `name` | string | ναι | Όνομα του νησιού, για εμφάνιση. |
| `width` | ακέραιος > 0 | ναι | Πλήθος στηλών του πλέγματος. |
| `height` | ακέραιος > 0 | ναι | Πλήθος γραμμών του πλέγματος. |
| `budget` | αριθμός ≥ 0 | ναι | Μέγιστη συνολική επένδυση (€) για νέες μονάδες. |
| `map` | πίνακας από string | ναι | Ο χάρτης, μία συμβολοσειρά ανά γραμμή. |
| `units` | πίνακας αντικειμένων | ναι | Οι υφιστάμενες μονάδες (ντιζελοστάσιο και φορτία). |
| `sites` | πίνακας αντικειμένων | ναι | Οι υποψήφιες θέσεις για νέες μονάδες. |

### 3.2 Ο χάρτης

Ο πίνακας `map` έχει ακριβώς `height` συμβολοσειρές, καθεμία με ακριβώς `width` χαρακτήρες. Κάθε χαρακτήρας είναι ένα κελί:

| Σύμβολο | Τύπος εδάφους |
| --- | --- |
| `~` | θάλασσα |
| `.` | ξηρά |
| `^` | βουνό |
| `H` | οικισμός |

Οι συντεταγμένες είναι `x` = στήλη και `y` = γραμμή, με αρχή το `(0, 0)` στην πάνω αριστερή γωνία. Ο χαρακτήρας του κελιού `(x, y)` είναι ο χαρακτήρας στη θέση `x` της συμβολοσειράς `map[y]`.

### 3.3 Υφιστάμενες μονάδες (`units`)

Κάθε στοιχείο έχει τα κοινά πεδία `id` (μοναδικό string), `type`, `x` και `y`, καθώς και τα πεδία του τύπου του.

**Ντιζελοστάσιο** (`"type": "DIESEL"`). Υπάρχει ακριβώς ένα σε κάθε σενάριο.

| Πεδίο | Περιγραφή | Όρια |
| --- | --- | --- |
| `pmin` | ελάχιστη ισχύς όταν λειτουργεί (kW) | 0 ≤ `pmin` ≤ `pmax` |
| `pmax` | μέγιστη ισχύς (kW) | > 0 |
| `fuel` | κόστος καυσίμου (€/kWh) | ≥ 0 |
| `co2` | εκπομπές (kg CO₂/kWh) | ≥ 0 |
| `start` | κόστος κάθε εκκίνησης (€) | ≥ 0 |

**Φορτίο** (`"type": "LOAD"`).

| Πεδίο | Περιγραφή | Όρια |
| --- | --- | --- |
| `category` | κατηγορία φορτίου, π.χ. `village`, `hotel` | πρέπει να υπάρχει ως στήλη σε όλα τα αρχεία CSV |
| `scale` | κλίμακα του φορτίου | > 0 |

Η ζήτηση ενός φορτίου την ώρα t είναι `scale × προφίλ_κατηγορίας(t) × 1000` kW. Για παράδειγμα, φορτίο με `scale` 0.35 και τιμή προφίλ 0.80 ζητά 280 kW.

### 3.4 Υποψήφιες θέσεις (`sites`)

| Πεδίο | Περιγραφή |
| --- | --- |
| `id` | μοναδικό string, π.χ. `s1` |
| `x`, `y` | θέση στον χάρτη |
| `allowed` | μη κενός πίνακας με τις τεχνολογίες που επιτρέπονται στη θέση: `PV`, `WIND`, `BATTERY` |

Σε κάθε θέση μπορεί να κατασκευαστεί **το πολύ ένα** στοιχείο του καταλόγου, και μόνο αν ο τύπος του περιέχεται στο `allowed`.

### 3.5 Κανόνες τοποθέτησης

- Καμία μονάδα και καμία θέση δεν βρίσκεται σε θάλασσα (`~`).
- Τα φορτία βρίσκονται μόνο σε κελιά οικισμού (`H`).
- Το ντιζελοστάσιο και οι υποψήφιες θέσεις βρίσκονται σε ξηρά (`.`) ή βουνό (`^`), όχι σε οικισμό.
- Δύο στοιχεία (μονάδες ή θέσεις) δεν μπορούν να βρίσκονται στο ίδιο κελί.
- Όλα τα `id` των `units` και των `sites` είναι μοναδικά μεταξύ τους.

## 4. Το αρχείο `catalog.json`

Περιέχει τα στοιχεία που μπορούν να κατασκευαστούν, σε έναν πίνακα `items`. Κάθε στοιχείο έχει τα κοινά πεδία:

| Πεδίο | Περιγραφή | Όρια |
| --- | --- | --- |
| `id` | μοναδικό αναγνωριστικό, π.χ. `pv100` | |
| `type` | `PV`, `WIND` ή `BATTERY` | |
| `size` | ονομαστική ισχύς (kW) για `PV`/`WIND`, χωρητικότητα (kWh) για `BATTERY` | > 0 |
| `capex` | κόστος επένδυσης (€) | ≥ 0 |
| `life` | διάρκεια ζωής (έτη) | > 0 |

**Επιπλέον πεδία ανεμογεννήτριας** (`WIND`): `cutin`, `rated`, `cutout` (m/s), με 0 ≤ `cutin` < `rated` < `cutout`.

**Επιπλέον πεδία μπαταρίας** (`BATTERY`): `pmax` (μέγιστη ισχύς φόρτισης και εκφόρτισης, kW, > 0), `eff` (απόδοση φόρτισης, 0 < `eff` ≤ 1), `soc_min` και `soc_max` (ελάχιστη και μέγιστη στάθμη ως κλάσμα της χωρητικότητας, 0 ≤ `soc_min` < `soc_max` ≤ 1).

Παράδειγμα:

```json
{
  "items": [
    {"id": "pv100", "type": "PV", "size": 100, "capex": 90000, "life": 25},
    {"id": "w150", "type": "WIND", "size": 150, "capex": 240000, "life": 20,
     "cutin": 3.0, "rated": 12.0, "cutout": 25.0},
    {"id": "b300", "type": "BATTERY", "size": 300, "capex": 120000, "life": 12,
     "pmax": 150, "eff": 0.90, "soc_min": 0.10, "soc_max": 0.95}
  ]
}
```

Το ίδιο στοιχείο του καταλόγου μπορεί να κατασκευαστεί σε περισσότερες από μία θέσεις.

## 5. Οι αντιπροσωπευτικές ημέρες (`days/`)

### 5.1 Αρχεία CSV

Κάθε αρχείο είναι μία ημέρα, με γραμμή επικεφαλίδας και ακριβώς 24 γραμμές δεδομένων, για τις ώρες 0 έως 23 με αυτή τη σειρά.

| Στήλη | Περιγραφή | Όρια |
| --- | --- | --- |
| `hour` | ώρα 0–23 | ακέραιος, διαδοχικός |
| `solar` | ηλιακός συντελεστής | 0–1 |
| `wind_ms` | ταχύτητα ανέμου σε επίπεδο ξηράς (m/s) | ≥ 0 |
| μία στήλη ανά κατηγορία φορτίου | κανονικοποιημένο προφίλ ζήτησης, π.χ. `village`, `hotel` | ≥ 0 |

Παράδειγμα:

```csv
hour,solar,wind_ms,village
0,0.000,11.3,0.330
1,0.000,12.8,0.297
...
12,0.356,6.9,0.605
```

Η σειρά των στηλών μετά τις τρεις πρώτες δεν είναι δεσμευτική: η εφαρμογή διαβάζει τις στήλες με βάση την επικεφαλίδα. Στήλες για κατηγορίες που δεν χρησιμοποιεί κανένα φορτίο αγνοούνται.

### 5.2 Το αρχείο `weights.json`

Ορίζει ποια αρχεία CSV ανήκουν στο σενάριο και πόσες ημέρες του έτους εκπροσωπεί το καθένα. Τα βάρη είναι θετικοί ακέραιοι με άθροισμα ακριβώς 365.

```json
{
  "weights": {
    "winter.csv": 90,
    "spring.csv": 92,
    "summer.csv": 92,
    "autumn.csv": 91
  }
}
```

Αρχεία CSV του φακέλου που δεν αναφέρονται στο `weights.json` αγνοούνται.

## 6. Πώς υπολογίζονται οι ποσότητες

Οι παρακάτω κανόνες συμπληρώνουν την ενότητα Α.1 της εκφώνησης. Είναι κοινοί για όλες τις ομάδες, ώστε το ίδιο σχέδιο να δίνει το ίδιο κόστος σε κάθε υλοποίηση.

**Φωτοβολταϊκό.** Παραγωγή = `size × solar`.

**Ανεμογεννήτρια.** Αν η θέση της είναι βουνό (`^`), η ταχύτητα ανέμου της ώρας πολλαπλασιάζεται επί 1.15. Με v την ταχύτητα που προκύπτει:

- v < `cutin` ή v ≥ `cutout`: παραγωγή 0,
- `cutin` ≤ v < `rated`: παραγωγή = `size × (v³ − cutin³) / (rated³ − cutin³)`,
- `rated` ≤ v < `cutout`: παραγωγή = `size`.

**Μπαταρία.** Κάθε ημέρα ξεκινά με στάθμη ίση με το 50% της χωρητικότητας. Όταν φορτίζει με ενέργεια E από το δίκτυο, η στάθμη αυξάνεται κατά `E × eff`. Όταν εκφορτίζει αποδίδοντας E στο δίκτυο, η στάθμη μειώνεται κατά E. Η στάθμη μένει πάντα μεταξύ `soc_min × size` και `soc_max × size`, και σε κάθε ώρα η ενέργεια φόρτισης ή εκφόρτισης δεν ξεπερνά το `pmax`. Μέσα σε μία ώρα μια μπαταρία είτε φορτίζει είτε εκφορτίζει, όχι και τα δύο.

**Πολλές μπαταρίες.** Ο ελεγκτής λειτουργίας τις χρησιμοποιεί διαδοχικά, με τη σειρά που εμφανίζονται οι θέσεις τους στον πίνακα `sites`: η πρώτη φορτίζει ή εκφορτίζει όσο μπορεί, και ό,τι απομένει περνά στην επόμενη.

**Ντιζελοστάσιο.** Μια εκκίνηση μετρά όταν το ντιζελοστάσιο λειτουργεί σε μια ώρα και δεν λειτουργούσε στην προηγούμενη. Κάθε ημέρα ξεκινά με το ντιζελοστάσιο εκτός λειτουργίας, οπότε η λειτουργία του στην ώρα 0 μετρά ως εκκίνηση.

**Ισότιμα σχέδια.** Δύο σχέδια με το ίδιο ετήσιο κόστος είναι εξίσου καλά. Για παράδειγμα, η μεταφορά ενός φωτοβολταϊκού σε άλλη θέση συχνά δεν αλλάζει το κόστος. Ο αυτόματος έλεγχος συγκρίνει την τιμή του κόστους, με ακρίβεια 1 €, και όχι τη συγκεκριμένη ανάθεση θέσεων.

## 7. Έλεγχοι εγκυρότητας

Κατά τη φόρτωση ενός σεναρίου η εφαρμογή σας πρέπει να ελέγχει τουλάχιστον τα παρακάτω. Για κάθε σφάλμα αναφέρει το αρχείο, το στοιχείο (π.χ. το `id` ή τη γραμμή του CSV) και ένα σαφές μήνυμα, χωρίς να τερματίζει.

1. Λείπει κάποιο από τα σταθερά αρχεία ή το JSON δεν είναι συντακτικά σωστό.
2. Λείπει υποχρεωτικό πεδίο ή έχει λάθος τύπο.
3. Ο χάρτης δεν έχει `height` γραμμές των `width` χαρακτήρων ή περιέχει άγνωστο σύμβολο.
4. Συντεταγμένες εκτός πλέγματος.
5. Παραβίαση κανόνα τοποθέτησης (ενότητα 3.5).
6. Δεν υπάρχει ακριβώς ένα ντιζελοστάσιο.
7. Θέση με κενό ή άγνωστο `allowed`.
8. Τιμή εκτός ορίων (π.χ. `soc_min` ≥ `soc_max`, `pmin` > `pmax`, `cutin` ≥ `rated`).
9. Διπλό `id` στον κατάλογο ή άγνωστος `type`.
10. Αρχείο CSV που δεν έχει 24 διαδοχικές ώρες, λείπει στήλη κατηγορίας φορτίου ή περιέχει μη αριθμητική τιμή.
11. Βάρη που δεν είναι θετικοί ακέραιοι ή δεν αθροίζουν σε 365, ή αρχείο του `weights.json` που δεν υπάρχει.

Ένα σενάριο με σφάλματα δεν φορτώνεται. Στον επεξεργαστή νησιού οι ίδιοι κανόνες ελέγχονται ζωντανά και τα άκυρα στοιχεία επισημαίνονται στον χάρτη.

## 8. Τα σενάρια που δίνονται

| Σενάριο | Νησί | Θέσεις | Ημέρες | Χαρακτήρας |
| --- | --- | --- | --- | --- |
| `a` | Νήσος Άλφα | 6 | 4 | Μικρό νησί με καλό αιολικό δυναμικό και δύο οικισμούς. Το ντιζελοστάσιο καλύπτει μόνο του τη ζήτηση, οπότε κάθε σχέδιο εντός προϋπολογισμού είναι αποδεκτό και το ζητούμενο είναι μόνο το κόστος. |
| `b` | Νήσος Βήτα | 8 | 6 | Τουριστικό νησί με δύο ξενοδοχεία. Στην ημέρα θερινής αιχμής το ντιζελοστάσιο δεν επαρκεί μόνο του, οπότε πολλά σχέδια δεν είναι αποδεκτά. Περιλαμβάνει ημέρα με άπνοια και συννεφιά. |

Και τα δύο σενάρια είναι αρκετά μικρά ώστε η εξαντλητική αναζήτηση να ολοκληρώνεται σε λίγα δευτερόλεπτα. Χρησιμοποιήστε τα για να ελέγξετε ότι η ευρετική σας βρίσκει το ίδιο κόστος.

## 9. Συμβουλές

- Φτιάξτε μικρά δικά σας σενάρια (π.χ. 3×3 με μία θέση και μία ημέρα), για τα οποία μπορείτε να υπολογίσετε το αποτέλεσμα με το χέρι. Είναι τα καλύτερα τεστ.
- Για τα τεστ εγκυρότητας, πάρτε ένα έγκυρο σενάριο και χαλάστε ένα πεδίο τη φορά.
- Το σχήμα των αρχείων για τα **σχέδια** και τα **αποτελέσματα** το ορίζετε εσείς (ενότητα Α.2 της εκφώνησης). Τεκμηριώστε το στην αναφορά σας.
